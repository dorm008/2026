(1). 열거형(enum TrafficLight { Red, Yellow, Green };)을 선언한 후 enum TrafficLight signal = Green;과 같이 변수를 선언하고 사용할 때의 이점으로 가장 거리가 먼 것은?

1: 매직 넘버(Magic Number)를 대체하여 코드의 가독성을 크게 향상시킨다.

2: 기존 정수형 변수보다 실행 속도가 압도적으로 빨라진다. (O)

3: 프로그램의 의도를 명확하게 표현하여 오류 발생 가능성을 줄여준다.

4: 관련된 상수들을 하나의 논리적 그룹으로 묶어 관리할 수 있다.

(2). 구조체 배열을 선언하고 초기화할 때, struct Student list[3] = {0};와 같이 작성하면 어떤 결과가 발생하는가?

1: 배열의 크기가 동적으로 0으로 줄어든다.

2: 문법 에러가 발생하여 배열을 생성할 수 없다.

3: 구조체 배열의 모든 멤버가 0 또는 널 문자 등으로 일괄 초기화된다. (O)

4: 첫 번째 학생의 데이터만 0이 되고 나머지 두 학생의 데이터는 쓰레기값으로 남는다.

(3). 공용체 Data에 정수와 문자열을 순서대로 저장할 때 발생하는 현상으로 가장 올바른 것은?

1: 문자열을 저장한 후 정수 값을 출력하면 문자열의 첫 글자가 아스키코드 정수로 자동 변환되어 출력된다.

2: 정수와 문자열이 메모리 상에 나란히 병치되어 두 값 모두 동시에 접근할 수 있다.

3: 컴파일 시점에 데이터 충돌로 인해 에러가 발생한다.

4: 가장 최근에 저장된 멤버의 값만이 유효하며, 이전 값은 덮어씌워진다. (O)

(4). 크기가 큰 구조체를 함수의 인수로 전달할 때, 값에 의한 전달(Call by Value) 대신 구조체 포인터를 전달하는 주된 이유가 아닌 것은?

1: 복잡한 데이터 구조를 효율적으로 함수 간에 공유하기 위해

2: 함수 내에서 원본 구조체의 멤버 값을 직접 수정하고 그 결과를 유지하기 위해

3: 함수 내부에서 원본 데이터의 변경을 원천적으로 차단하기 위해 (O)

4: 구조체 전체를 복사하는 오버헤드를 줄여 메모리 사용과 성능을 최적화하기 위해

(5). 구조체 변수 간의 대입 연산(=)을 수행할 때, 구조체 내부에 포인터 멤버가 포함되어 있다면 복사 과정에서 어떤 현상이 발생하는가?

1: 포인터가 가리키는 동적 메모리 공간까지 완벽하게 새로운 공간에 복사되는 깊은 복사가 일어난다.

2: 포인터가 가리키는 실제 데이터는 복사되지 않고 메모리 주소값만 복사되는 얕은 복사가 발생한다. (O)

3: 컴파일 에러가 발생하여 포인터 멤버가 포함된 구조체는 대입할 수 없다.

4: 포인터 멤버의 주소값이 자동으로 초기화되어 NULL로 설정된다.
